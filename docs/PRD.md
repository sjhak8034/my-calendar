# my-calendar PRD

## 1. 핵심 정보
- 목적: 월간 캘린더에서 일정을 관리하고, 선택한 날짜 범위의 일정에 대해 AI와 대화하며 확인하고, 일정 시작 전·종료 시 알림을 받는다.
- 대상 사용자: 개인 사용자 본인(개인용으로 시작). 이후 다중 사용자 서비스로 확장하므로 모든 데이터는 사용자 단위로 분리한다.

## 2. 사용자 여정
1. 이메일 또는 Google로 로그인한다.
2. 월간 캘린더에서 한 달 일정을 보고, 여러 날에 걸친 일정은 막대로 확인한다.
3. 날짜를 눌러 시간 단위 타임라인을 열고 일정을 생성·수정·삭제한다.
4. 설정에서 웹 푸시를 켜고 카카오를 연결한다. 일정 시작 10분 전과 종료 시각에 알림을 받는다.
5. 화면 오른쪽 아래 AI 대화 버튼을 눌러 채팅창을 열고, 대화하듯 일정을 물어보거나(AI가 직접 일정을 검색) 일정 작성을 맡긴다(작성·수정·삭제는 확인 버튼을 거친다).

## 3. 기능 명세
| ID | 기능 | 설명 | 연결 페이지 |
| --- | --- | --- | --- |
| F001 | 이메일 로그인 | 이메일 가입·로그인 (Supabase Auth). 이메일 확인이 켜져 있으면 가입 후 "확인 메일을 보냈어요" 안내를 보여 주고, 메일의 링크(가입을 시작한 브라우저에서만 마무리됨)를 누르면 로그인됨. 확인 전 로그인은 확인 안내와 확인 메일 재발송을 보여 줌. 비밀번호는 8자 이상 + 영문·숫자 포함. 비밀번호를 잊으면 이메일로 재설정 링크를 받아 새 비밀번호를 정하고(바꾸면 다른 기기의 로그인은 해제) | 로그인, 비밀번호 찾기, 새 비밀번호 설정 |
| F002 | Google 로그인 | 소셜 로그인 | 로그인 |
| F003 | 로그아웃·접근 제어 | 로그아웃하고, 비로그인 상태로 로그인 외 모든 페이지에 접근하면 로그인 화면으로 이동 | 로그인, 월간 캘린더, 날짜 상세, AI 대화, 설정 |
| F004 | 월간 보기와 날짜 이동 | 한 달 그리드, 이전/다음/오늘 이동, 날짜별 일정 표시 | 월간 캘린더 |
| F005 | 다일 일정 막대 | 여러 날 일정은 주 단위 막대로 표시(**종일·여러 날 일정에는 옅은 사선 무늬**가 있어 시간이 정해진 일정과 구분됨. 월간 막대와 주간 종일 줄·시간 블록 모두 같은 기준), 한 날짜 일정이 많으면 "+N개"로 축약 | 월간 캘린더 |
| F006 | 날짜 상세 타임라인 | 날짜 선택 시 그 날짜가 속한 주(월요일 시작)의 7열 시간 타임라인(06:00~24:00)과 0~6시 일정을 모으는 "6시 이전" 줄을 표시하고 선택한 날짜 열을 강조. 일정을 누르면 오른쪽 사이드바에서 내용을 보고 수정 | 날짜 상세 |
| F007 | 일정 생성 | 오른쪽 사이드바에 제목, 시작·종료, 종일 여부, 설명, 색상 입력. 주간 그리드의 초안 블록을 끌어 요일·시간을 정하고 위·아래 가장자리로 길이를 조절(15분 단위). **월간 그리드에서는 날짜 칸을 마우스로 끌어 기간(예: 20일~25일)을 고르면 같은 사이드바가 월간 화면에서 열리고 종일 일정(종료일 포함)으로 만들어진다.** 터치에서는 끌 수 없어 툴바의 "일정 추가"(오늘 하루짜리 종일 일정, 폼의 날짜로 기간을 늘림)를 쓴다 | 월간 캘린더, 날짜 상세 |
| F008 | 일정 수정 | 사이드바에서 속성 변경, 시간 일정은 그리드에서 끌어 이동·크기 조절(놓는 즉시 저장). **터치(휴대폰)에서는 일정을 약 0.4초 길게 누르면 떠올라 끌 수 있고(아이폰 캘린더 방식), 문지르면 스크롤된다.** **월간 화면에서는 일정 막대를 눌러 수정 입력창을 열고, 마우스로 막대를 끌어 통째로 옮기거나(기간 길이·시간 유지) 종일 막대의 양 끝을 끌어 시작일·종료일을 바꾼다(놓으면 저장, 서버가 다시 그릴 때까지 새 구간을 하이라이트)** | 월간 캘린더, 날짜 상세 |
| F009 | 일정 삭제 | 확인 후 삭제 | 날짜 상세 |
| F010 | AI 대화(팝업 채팅) | 오른쪽 아래 둥근 버튼(**휴대폰은 주간 그리드를 가리지 않도록 상단 바의 로고와 메뉴 버튼 사이에 작게**)으로 여는 채팅 팝업에서 AI(Google Gemini)와 대화. AI가 도구(`search_events`)로 질문에서 짐작한 기간의 본인 일정을 직접 검색해 답한다. 일정 추가·수정·삭제는 AI가 카드(수정은 변경 전/후)를 제시하고 사용자가 확인 버튼을 눌러야 실행. 메시지는 200자 이하, 사용자별 시간당 20회·하루 100회로 제한. 이어지는 단일 대화 + 새 대화 버튼, 대화는 저장하고 마지막 대화 후 30일이 지나면 삭제하며 사용자가 전체 삭제할 수 있음 | 모든 앱 화면(공통) |
| F011 | 알림 예약 | 일정 저장 시 시작 10분 전·종료 시각 알림을 예약(종일 일정 제외), 수정·삭제 시 갱신 | 날짜 상세 |
| F012 | 웹 푸시 설정 | 브라우저 알림 권한 허용과 구독 등록·해제. 로그아웃하면 이 브라우저의 구독을 해제하고(공유 기기에서 이전 사용자의 알림이 계속 뜨지 않게), 푸시를 켜 둔 계정이 같은 브라우저(알림 권한이 이미 허용된 곳)에서 다시 로그인하면 자동으로 다시 구독 | 설정 |
| F013 | 카카오 연결 | 카카오톡 "나에게 보내기" 연결·해제 (로그인과 별개). 게스트는 연결할 수 없고 계정 만들기를 안내하는 팝업을 보여 줌 | 설정 |
| F014 | 알림 발송 | 예약 시각이 된 알림을 일정 소유자 본인에게 웹 푸시·카카오톡으로 발송(카카오 토큰이 만료되면 갱신 후 발송)하고 채널별 결과 상태 표시 | 설정 |
| F015 | 게스트로 시작 | 로그인 화면의 "게스트로 시작"으로 가입 없이 익명 로그인(Supabase 익명 인증). 일정은 이 브라우저 세션에 묶이고 마지막 활동 후 30일이 지나면 삭제. 게스트의 AI 대화는 하루(최근 24시간) 3회로 제한(DB 함수가 강제). 로그아웃하면 계정과 데이터가 즉시 삭제되므로 확인 대화상자를 거침(로그아웃 없이 버려진 게스트는 30일 뒤 삭제) | 로그인, 모든 앱 화면 |
| F016 | 게스트 → 정식 계정 전환 | 게스트 데이터를 유지한 채 이메일·비밀번호 또는 Google 계정을 연결| 계정 만들기 |
| F017 | 계정 삭제 | 정식 계정이 설정 화면에서 계정과 모든 데이터(일정, AI 대화, 푸시 구독, 카카오 토큰, 알림 기록)를 영구 삭제. 되돌릴 수 없어 가입한 이메일을 입력해야 삭제되고, 카카오 연결 끊기와 브라우저 푸시 해제도 함께 시도. 게스트는 로그아웃 시 삭제되는 기존 흐름을 씀 | 설정 |
| F018 | 날짜별 날씨·기온 표시 | 오늘부터 약 2주(최대 16일) 예보를 날짜별 날씨 아이콘(맑음·구름 조금·흐림·안개·이슬비·비·눈·천둥번개)과 최저/최고 기온으로 보여 줌. **월간은 날짜 숫자 옆에 아이콘만**(기온은 마우스를 올리면 툴팁), **주간은 요일 앞 아이콘 + 머리글 한 줄 아래 작은 기온**. 지역은 **브라우저 위치**(허용하지 않거나 못 받으면 서울), 위치는 기기 안에서만 쓰고 반올림한 좌표(약 1km)만 날씨 서비스(Open-Meteo)로 감(서버·DB에 저장하지 않음). 예보 밖 날짜·지난 날짜·받지 못했을 때는 아이콘 없이 비움. 그리드 아래에 출처 표기 | 월간 캘린더, 날짜 상세 |

## 5. 페이지별 상세
### 로그인 (`/login`)
- 구현 기능: F001, F002, F003
- 구성 요소: 이메일·비밀번호 폼, Google 로그인 버튼, 가입/로그인 전환
- 주요 상호작용: 로그인 성공 시 월간 캘린더로 이동, 실패 시 오류 메시지 표시

### 월간 캘린더 (`/`)
- 구현 기능: F003, F004, F005, F018
- 구성 요소: 좌측 사이드바(로고, 메뉴, 사용자 카드), 날짜 배지·월 제목·이전/오늘/다음 툴바, 요일 헤더(월~일), 6주 × 7일 고정 날짜 그리드, 일정 칩과 여러 날 일정 막대(한 칸 최대 3줄, 넘치면 "N개 더 보기")
- 일정 색: 팔레트 8종(gray, blue, indigo, purple, pink, orange, yellow, green), 알 수 없는 값은 gray
- 주요 상호작용: 날짜 클릭 시 날짜 상세로 이동(다른 칸까지 끌면 이동 대신 기간 일정 입력창이 열림), **일정 막대를 누르면 주간 화면으로 이동하지 않고 월간 화면에서 수정 입력창이 열림(Ctrl·⌘·Shift 클릭과 가운데 버튼은 링크대로 주간 화면)**, "N개 더 보기" 클릭 시 해당 날짜 상세로 이동, `?month=YYYY-MM`으로 달 선택(값이 없거나 잘못되면 오늘이 속한 달로 redirect)

### 날짜 상세 (`/day/[date]`)
- 구현 기능: F006, F007, F008, F009, F011, F018
- 구성 요소: 그 날짜가 속한 주의 7열 주간 화면(06~24시 시간 눈금, 색 블록 일정, 겹치는 일정은 열 분할, "6시 이전" 줄, 현재 시각 점선, 선택 날짜 열 강조, 헤더·종일 줄 고정), 일정 입력·수정 사이드바, 이전/다음 주·오늘·월간 보기 이동, 일정 입력 사이드바(Task 008)
- 모바일: **휴대폰(640px 미만)은 7일·06~24시가 스크롤 없이 한 화면에 보이게 압축**(열 최소 너비 없음, 시간 눈금 열 2rem에 **2시간 단위(6, 8, 10…) 24시간제 숫자**, 주간 페이지는 상단 바를 뺀 화면 높이로 고정되고 그리드가 남은 높이를 채워 **페이지·그리드 모두 스크롤이 없음**(**주간 그리드에는 웹·모바일 모두 "종일" 줄을 두지 않는다**(사용자 결정): 종일·여러 날 일정은 월간 보기에서 본다)(종일 일정 줄·"6시 이전" 줄이 있어도 시간 간격이 자동으로 맞춰짐, 최소 0.875rem; "주간 일정" 제목은 눈에는 숨김, 터치의 크기 조절 핸들은 쓰지 않음), 머리글은 요일·날짜·날씨 아이콘·최저/최고 기온(`7°/18°`)을 세로로, 일정 블록은 제목만 한 줄, 45분 미만은 9px). 아래의 "선택한 날 일정 목록"은 두지 않는다(사용자 요청으로 제거). 640px 이상은 시간당 3.5rem, 7열 + 가로 스크롤(시간 눈금 열 고정)이고 선택한 날짜 열이 보이도록 초기 스크롤
- 주요 상호작용: 빈 시간대 클릭으로 생성, 일정 클릭으로 수정·삭제, 저장 시 알림 예약 갱신

### AI 대화 (팝업, 모든 앱 화면 공통)
- 구현 기능: F010
- 구성 요소: 오른쪽 아래 둥근 버튼(아이콘은 추후 교체), 채팅 팝업(작은 화면은 전체 화면), 메시지 목록, 입력창(200자), 새 대화·기록 삭제 버튼
- 주요 상호작용: 열면 가장 최근 대화(30일 이내)를 이어서 보여 줌. 질문 전송, 응답 스트리밍 표시·중단, 일정 검색 중 표시. 사용량 제한 도달 시 안내. 새 대화 시작, 기록 전체 삭제(확인 후). AI의 추가·수정·삭제는 확인 카드의 버튼으로만 실행. 질문에 따라 일정의 제목·설명이 Google Gemini로 전송되고 대화가 30일간 저장된다는 안내를 팝업에 표시

### 설정 (`/settings`)
- 구현 기능: F012, F013, F014
- 구성 요소: 웹 푸시 토글, 카카오 연결 상태·버튼, 최근 알림 발송 상태 목록
- 주요 상호작용: 푸시 권한 요청과 구독 해제, 카카오 동의 화면 이동과 연결 해제

## 6. 데이터 모델
- Event: id, user_id, title, start_at, end_at, all_day, description, color
- Notification: id, user_id, event_id, kind(시작 전/종료), channel(웹 푸시/카카오), send_at, sent_at, status(대기/발송 중/발송됨/실패/건너뜀), error(사유 코드)
- AiConversation: id, user_id, start_date, end_date, title(첫 질문), created_at, updated_at(마지막 대화 시각, 보관 30일의 기준)
- AiMessage: id, conversation_id, user_id, role(user/assistant), content, created_at
- AiRequest: id, user_id, created_at (사용량 제한용 기록. 정책 없이 서버 함수로만 접근)
- PushSubscription: id, user_id, endpoint, keys, lang(알림 문구 언어)
- KakaoConnection: user_id, access_token, refresh_token, expires_at, refresh_expires_at, lang(알림 문구 언어), needs_reconnect(재연결 필요 표시) (토큰은 암호화하여 저장)
- 사용자 계정은 Supabase Auth가 관리한다.
- 모든 테이블에 행 수준 보안(RLS)을 적용해 본인 데이터만 접근하게 한다(AiRequest는 정책 없이 서버 함수로만 접근). AI 대화는 마지막 대화 후 30일이 지나면 조회에서 제외되고 삭제 함수로 정리된다.

## 7. 기술 스택
- Next.js `16.4.3` (App Router), React `19.3.0`, TypeScript `^5` (strict), Tailwind CSS `^4`, shadcn/ui `base-nova`, `lucide-react` (설치 완료)
- 추가 결정: Supabase(Auth·DB), Gemini API(Google AI Studio), Vercel 배포
- 알림 발송: Supabase `pg_cron`이 1분마다 Vercel의 서버 엔드포인트를 호출한다.
- 개인정보(게스트): 익명 계정의 일정·AI 대화도 같은 DB에 저장되며, 게스트가 로그아웃하면 즉시 삭제하고 로그아웃 없이 버려진 계정은 마지막 활동 후 30일이 지나면 삭제한다. 처리방침 문구는 Task 013에서 반영한다.
- 개인정보: AI 대화에 일정의 제목·설명이 Google Gemini로 전송되고, 질문·답변이 DB에 30일간 저장된다. 일정을 지워도 이미 저장된 대화 안의 내용은 보관 기간 동안 남는다. 개인정보처리방침 문구는 Task 013에서 반영한다.
- 가정: 타임존 `Asia/Seoul`, 한국어/영어 지원(모든 경로는 `/[lang]` 접두사), 주 시작 월요일, 월/주 보기 전환 메뉴는 없음(날짜 상세가 주간 화면 역할), 화면에 보이는 요일·월·날짜 제목은 언어와 무관하게 영어 3글자 약어(Mon, Oct 등)

## 8. 확인 필요 사항
- 확정: 주 시작 월요일, 월간 그리드 6주 × 7일 고정(월요일 시작에서 31일 달이 토·일에 시작하거나 30일 달이 일요일에 시작하면 6줄이 필요), 한 날짜 칸 최대 3줄 + "N개 더 보기", 일정 색은 팔레트 8종, 종료<시작은 DB 제약(`end_at >= start_at`)으로 거부
- 확정(Task 009): AI는 도구로 일정을 직접 검색(한 번에 최대 366일·50건, 질문당 모델 호출 최대 5회), 메시지 200자, 사용자별 시간당 20회·하루 100회(롤링), 이어 질문 맥락은 최근 10개 메시지(8,000자), 설명 300자 절단, 대화 보관은 마지막 대화 후 30일
- 확정(Task 008): 종료는 사용자가 입력한 종료일·종료 시각을 그대로 저장(종일 일정도 날짜와 시각을 입력, 종일 켜면 기본 00:00~23:59). 종료<시작은 폼·서버에서 "종료는 시작 이후여야 합니다"로 먼저 거부. 화면 규칙: 종료가 서울 기준 정확히 00:00이고 시작 날짜보다 늦으면 전날까지 표시
- 일정 규칙 결정(Task 010 확정): 일정의 시작·종료·종일 여부가 바뀌면 이미 발송된 알림도 지우고 새 시각으로 다시 예약한다(제목·설명 수정은 알림을 건드리지 않음). 이미 지난 시각의 알림은 만들지 않고, 발송 시각에서 10분 넘게 늦으면 보내지 않는다
- 잘못된 날짜 경로(`/day/abc` 등)는 화면은 404이지만 HTTP 상태는 200(Suspense 안의 `notFound()`). 상태 코드가 필요하면 프록시에서 경로를 검증(Task 013에서 결정)
- Vercel Cron, Supabase `pg_cron` 요금제별 제한
- 카카오 `talk_message` 동의 항목의 다중 사용자 제공 조건(검수 여부)
- 가정 확인: 종료 알림은 종료 시각 정각, 종일 일정은 알림 제외. AI 대화 기록은 저장(30일 보관)으로 변경됨
- MVP 제외(후속): 반복 일정, 검색, 월/주 보기 전환 메뉴, 드래그 편집, 구글 캘린더 가져오기, 공유/초대, AI의 일정 직접 수정, 알림 시점 사용자 설정
