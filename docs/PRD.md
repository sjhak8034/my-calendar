# my-calendar PRD

## 1. 핵심 정보
- 목적: 월간 캘린더에서 일정을 관리하고, 선택한 날짜 범위의 일정에 대해 AI와 대화하며 확인하고, 일정 시작 전·종료 시 알림을 받는다.
- 대상 사용자: 개인 사용자 본인(개인용으로 시작). 이후 다중 사용자 서비스로 확장하므로 모든 데이터는 사용자 단위로 분리한다.

## 2. 사용자 여정
1. 이메일 또는 Google로 로그인한다.
2. 월간 캘린더에서 한 달 일정을 보고, 여러 날에 걸친 일정은 막대로 확인한다.
3. 날짜를 눌러 시간 단위 타임라인을 열고 일정을 생성·수정·삭제한다.
4. 설정에서 웹 푸시를 켜고 카카오를 연결한다. 일정 시작 10분 전과 종료 시각에 알림을 받는다.
5. AI 대화 화면에서 날짜 범위를 지정하고 그 범위의 일정에 대해 질문한다.

## 5. 페이지별 상세
### 로그인 (`/login`)
- 구현 기능: F001, F002, F003
- 구성 요소: 이메일·비밀번호 폼, Google 로그인 버튼, 가입/로그인 전환
- 주요 상호작용: 로그인 성공 시 월간 캘린더로 이동, 실패 시 오류 메시지 표시

### 월간 캘린더 (`/`)
- 구현 기능: F003, F004, F005
- 구성 요소: 좌측 사이드바(로고, 메뉴, 사용자 카드), 날짜 배지·월 제목·이전/오늘/다음 툴바, 요일 헤더(월~일), 6주 × 7일 고정 날짜 그리드, 일정 칩과 여러 날 일정 막대(한 칸 최대 3줄, 넘치면 "N개 더 보기")
- 일정 색: 팔레트 8종(gray, blue, indigo, purple, pink, orange, yellow, green), 알 수 없는 값은 gray
- 주요 상호작용: 날짜 클릭 시 날짜 상세로 이동, "N개 더 보기" 클릭 시 해당 날짜 상세로 이동, `?month=YYYY-MM`으로 달 선택

### 날짜 상세 (`/day/[date]`)
- 구현 기능: F006, F007, F008, F009, F011
- 구성 요소: 그 날짜가 속한 주의 7열 주간 화면(06~24시 시간 눈금, 색 블록 일정, 겹치는 일정은 열 분할, 종일 일정 줄, "6시 이전" 줄, 현재 시각 점선, 선택 날짜 열 강조, 헤더·종일 줄 고정), 일정 입력·수정 사이드바, 이전/다음 주·오늘·월간 보기 이동, 일정 입력 사이드바(Task 008)
- 모바일: 7열 유지 + 가로 스크롤(시간 눈금 열 고정), 선택한 날짜 열이 보이도록 초기 스크롤
- 주요 상호작용: 빈 시간대 클릭으로 생성, 일정 클릭으로 수정·삭제, 저장 시 알림 예약 갱신

### AI 대화 (`/ai`)
- 구현 기능: F010
- 구성 요소: 시작일·종료일 선택, 범위 내 일정 개수 표시, 대화 목록, 입력창
- 주요 상호작용: 범위 지정 후 질문 전송, 응답 스트리밍 표시. 범위 상한 초과 시 안내. 새로고침하면 대화 초기화

### 설정 (`/settings`)
- 구현 기능: F012, F013, F014
- 구성 요소: 웹 푸시 토글, 카카오 연결 상태·버튼, 최근 알림 발송 상태 목록
- 주요 상호작용: 푸시 권한 요청과 구독 해제, 카카오 동의 화면 이동과 연결 해제

## 6. 데이터 모델
- Event: id, user_id, title, start_at, end_at, all_day, description, color
- Notification: id, user_id, event_id, kind(시작 전/종료), channel(웹 푸시/카카오), send_at, sent_at, status(대기/발송/실패)
- PushSubscription: id, user_id, endpoint, keys
- KakaoConnection: user_id, access_token, refresh_token, expires_at (토큰은 암호화하여 저장)
- 사용자 계정은 Supabase Auth가 관리한다.
- 모든 테이블에 행 수준 보안(RLS)을 적용해 본인 데이터만 접근하게 한다.

## 7. 기술 스택
- Next.js `16.4.3` (App Router), React `19.3.0`, TypeScript `^5` (strict), Tailwind CSS `^4`, shadcn/ui `base-nova`, `lucide-react` (설치 완료)
- 추가 결정: Supabase(Auth·DB), OpenAI API, Vercel 배포
- 알림 발송: Supabase `pg_cron`이 1분마다 Vercel의 서버 엔드포인트를 호출한다.
- 가정: 타임존 `Asia/Seoul`, 한국어/영어 지원(모든 경로는 `/[lang]` 접두사), 주 시작 월요일, 월/주 보기 전환 메뉴는 없음(날짜 상세가 주간 화면 역할), 화면에 보이는 요일·월·날짜 제목은 언어와 무관하게 영어 3글자 약어(Mon, Oct 등)

## 8. 확인 필요 사항
- 확정: 주 시작 월요일, 월간 그리드 6주 × 7일 고정(월요일 시작에서 31일 달이 토·일에 시작하거나 30일 달이 일요일에 시작하면 6줄이 필요), 한 날짜 칸 최대 3줄 + "N개 더 보기", 일정 색은 팔레트 8종, 종료<시작은 DB 제약(`end_at >= start_at`)으로 거부
- 수치 결정: AI 대화 범위 상한(최대 일수), 사용자별 AI 사용량 제한
- 확정(Task 008): 종료는 사용자가 입력한 종료일·종료 시각을 그대로 저장(종일 일정도 날짜와 시각을 입력, 종일 켜면 기본 00:00~23:59). 종료<시작은 폼·서버에서 "종료는 시작 이후여야 합니다"로 먼저 거부. 화면 규칙: 종료가 서울 기준 정확히 00:00이고 시작 날짜보다 늦으면 전날까지 표시
- 일정 규칙 결정: 일정 수정 시 이미 발송된 알림 처리(Task 010)
- 잘못된 날짜 경로(`/day/abc` 등)는 화면은 404이지만 HTTP 상태는 200(Suspense 안의 `notFound()`). 상태 코드가 필요하면 프록시에서 경로를 검증(Task 013에서 결정)
- Vercel Cron, Supabase `pg_cron` 요금제별 제한
- 카카오 `talk_message` 동의 항목의 다중 사용자 제공 조건(검수 여부)
- 가정 확인: 종료 알림은 종료 시각 정각, 종일 일정은 알림 제외, AI 대화 기록 미저장
- MVP 제외(후속): 반복 일정, 검색, 월/주 보기 전환 메뉴, 드래그 편집, 구글 캘린더 가져오기, 공유/초대, AI의 일정 직접 수정, 알림 시점 사용자 설정
