# my-calendar ROADMAP

월간 캘린더, 날짜별 시간 상세, 날짜 범위 AI 대화, 시작·종료 알림(웹 푸시 + 카카오톡)을 만드는 개발 로드맵. 요구사항은 `docs/PRD.md`를 따른다.

**📅 최종 업데이트**: 2026-10-25
**📊 진행 상황**: Phase 1 대기 중 (0/13 Tasks 완료)

## 착수 전 결정 사항

- 주 시작 요일(일/월): Task 005 전
- AI 대화 범위 상한과 사용자별 사용량 제한 수치: Task 009 전
- 한 날짜 셀 표시 일정 수("+N개" 기준), 색상 입력 방식, 종료<시작 검증, 종일 다일 일정의 종료일 포함 여부: Task 006~008 전
- Vercel Cron / Supabase `pg_cron`·`pg_net` 요금제별 제한 확인: Task 010 전
- 카카오 `talk_message` 동의 항목의 다중 사용자 제공 조건(검수 여부): Task 012 전
- Next.js 16의 인증 확인 위치는 `node_modules/next/dist/docs/` 확인 후 결정: Task 003 전

## 개발 단계

### Phase 1: 프로젝트 기반

- **Task 001: 초기 템플릿 정리 및 프로젝트 설정** - 우선순위
  - `create-next-app` 데모 콘텐츠와 미사용 `public/` 에셋 제거
  - `README.md`를 캘린더 프로젝트 설명으로 교체
  - 루트 레이아웃·전역 스타일 확인(한국어 `lang`, 폰트, `.dark` 테마 토큰)
  - `npm run lint`, `npm run build` 통과 확인
- **Task 002: Supabase 프로젝트·스키마·RLS 구성** - 우선순위
  - Supabase 프로젝트 생성과 환경변수 구성(`.env.local`, Vercel)
  - `lib/supabase/` 서버·클라이언트 생성기(`@supabase/ssr`)
  - 테이블 생성: `events`, `notifications`(channel, status 포함), `push_subscriptions`, `kakao_tokens`
  - 모든 테이블에 `user_id` + RLS 정책 적용
- **Task 003: 인증 (이메일 + Google) 및 접근 제어** - 우선순위
  - 로그인 페이지(`/login`): 이메일 가입·로그인, Google 로그인 버튼
  - 비로그인 시 로그인 외 모든 페이지에서 `/login`으로 이동
  - 로그아웃, 로그인 실패 오류 메시지
  - 앱 공통 레이아웃과 메뉴(캘린더, AI 대화, 설정, 로그아웃)

### Phase 2: 캘린더 핵심

- **Task 004: 날짜 유틸 및 공통 UI 컴포넌트** - 우선순위
  - `lib/calendar/` 순수 함수: 월 그리드 생성, 주 단위 분할, 날짜 비교(`Asia/Seoul`, `Date` 변이 금지)
  - 월 경계·윤년 케이스 수동 검증 목록 정리
  - 필요한 shadcn 컴포넌트 추가(`npx shadcn@latest add`: dialog, input 등)
- **Task 005: 월간 캘린더 보기 (F004)** - 우선순위
  - 월 그리드, 요일 헤더, 이전/다음/오늘 이동
  - 날짜 셀 클릭 시 `/day/[date]`로 이동
  - 접근성: `role="grid"`, `aria-current="date"`, `<time>`
  - 모바일 반응형 레이아웃
- **Task 006: 다일 일정 막대 (F005)** - 우선순위
  - 여러 날 일정을 주 단위로 분할해 막대로 표시, 주를 넘기면 이어서 표시
  - 겹치는 일정의 레인 배정
  - 셀 한도 초과 시 "+N개" 표시와 클릭 동작
- **Task 007: 날짜 상세 타임라인 (F006)** - 우선순위
  - `/day/[date]` 페이지, 24시간 타임라인과 종일 일정 영역
  - 겹치는 일정의 컬럼 분할
  - 이전/다음 날 이동
- **Task 008: 일정 생성·수정·삭제 (F007~F009)** - 우선순위
  - 일정 입력 폼(제목, 시작·종료, 종일 여부, 설명, 색상)과 입력 검증
  - 빈 시간대 클릭으로 생성, 일정 클릭으로 수정·삭제(삭제 전 확인)
  - Server Action 또는 Route Handler로 저장, 저장 후 화면 갱신

### Phase 3: AI 대화

- **Task 009: 날짜 범위 AI 대화 (F010)** - 우선순위
  - `/ai` 페이지: 시작일·종료일 선택, 범위 내 일정 개수 표시
  - `app/api/ai/route.ts`: 범위 내 본인 일정 조회 후 OpenAI 스트리밍 응답
  - 범위 상한, 사용자별 사용량 제한, 일정 내용을 지시와 구분해 전달(프롬프트 인젝션 방어)
  - API 키는 서버 환경변수에만 보관, 대화 기록은 저장하지 않음

### Phase 4: 알림

- **Task 010: 알림 예약 및 발송 워커 (F011, F014)** - 우선순위
  - 일정 저장 시 시작 10분 전·종료 시각 알림 행 생성(종일 일정 제외), 수정·삭제 시 갱신·취소
  - `app/api/cron/notify/route.ts`: 공유 비밀 헤더 검증, 발송 시각이 된 알림 조회 후 발송
  - Supabase `pg_cron` + `pg_net`으로 1분마다 호출
  - 중복 발송 방지(상태 컬럼 + 원자적 갱신)
- **Task 011: 웹 푸시 알림 (F012)** - 우선순위
  - `public/sw.js` 서비스 워커, VAPID 키 구성
  - 설정 페이지(`/settings`): 푸시 권한 요청, 구독 등록·해제
  - 서버에서 웹 푸시 발송, 발송 결과 기록
- **Task 012: 카카오톡 알림 (F013, F014)** - 우선순위
  - 카카오 개발자 앱 등록, `talk_message` 동의 항목 설정
  - 설정 페이지에서 카카오 연결·해제(로그인과 별개)
  - 토큰 암호화 저장, 만료 시 갱신 후 발송, 갱신 실패 시 재연결 안내
  - 설정 페이지에 채널별 최근 발송 상태 목록 표시

### Phase 5: 마무리

- **Task 013: 품질 점검 및 배포** - 우선순위
  - `code-reviewer`로 전체 리뷰, 접근성·반응형 점검
  - 수동 시나리오: 월 경계·윤년, 월을 넘는 다일 일정, 한 날짜 일정 5개 이상, 비로그인 접근 차단, 타 사용자 데이터 접근 불가(RLS), AI 범위 상한 초과, 알림 중복 발송 여부
  - 11분 뒤 일정으로 웹·카카오톡 알림 end-to-end 확인
  - `npm run lint`, `npm run build` 통과 후 Vercel 배포
